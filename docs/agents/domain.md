# Domain docs

Layout: single-context per repository.

Before exploring, read root `GLOSSARY.md` and relevant ADRs
under `docs/adr/`.

If absent, proceed silently. Domain modeling creates these
lazily as terminology and decisions are resolved.

Use glossary terms in issues, proposals, hypotheses, and tests.
Note missing concepts for domain modeling.

Explicitly flag proposals that contradict existing ADRs,
identifying the ADR and reason for reopening it.
